# Every Share Votes

An independent, neutral site for retail holders of TSLA. It explains what is on the public record about a possible combination with SpaceX, how a vote is likely to be counted, and how to cast a ballot when a proxy exists.

Jason Crawford, an independent retail shareholder, maintains the project. It is not affiliated with Tesla, Inc. or SpaceX. It is not investment advice and not a solicitation.

The brand is “Every Share Votes.” The ticker TSLA is used for the stock. The company name appears when a filing or a statute uses it.

## Pages

## What is real, and what is not

Real in this repository:

- Page copy is tied to SEC filings, the Texas statute, the company’s vote guide and retail-voting page, or a named news report. Counts are the figures in those sources.
- `public/data/holders.json` is generated by `scripts/fetch_13f.py` from the SEC Form 13F data set. Every row has the filing’s EDGAR index URL, filing date, and report period.
- The share ledger stores rows in D1 and the public totals are sums of `status = counted` only.
- `public/data/sentiment.json` is generated by `scripts/fetch_sentiment.py` from Polymarket’s public price history and, when it returns data, the GDELT DOC API. Days that were not returned are not invented.
- `public/data/institutional-votes.json` is generated by `scripts/fetch_npx.py` from EDGAR N-PX XML. Each filled cell links to the filing it was read from.

Not filled in, on purpose:

- No proxy for a combination exists, so no record date, price, or voting standard is stated as final. The charter reading is marked unconfirmed.
- An institutional cell stays “Not found” when the N-PX run did not parse a matching row. The 2016 and 2018 meetings are not parsed from older text filings. Norges Bank does not file N-PX.
- ISS and Glass Lewis cells are filled only where a report or a company filing states the recommendation. Glass Lewis on the 2016 SolarCity vote is “Not found.” Glass Lewis on the 2025 xAI proposal is “Not found.”
- Webull is not in Tesla’s broker list. That card points at the guide’s “all other brokers” steps. SoFi and Public are choices on the self-reported form only.
- The ledger does nothing useful until a D1 database is created, both migrations are applied, and `DB`, `IP_HASH_SALT`, and `TURNSTILE_SECRET_KEY` are set. A missing binding is an error, not a fake zero.
- Kalshi is “No market yet” unless the fetch script finds a matching market. It is not given a price.
- The weekly 13F Action and the daily sentiment Action open a pull request only when the JSON changes. Set `SEC_CONTACT_EMAIL` to a mailbox a person reads. Until then the SEC scripts fall back to `contact@everysharevotes.com` and print a warning.

## Local development

Requires Node 20 or newer and Python 3.12.

```bash
npm install
npm run dev
```

The dev server is Astro. The ledger is a Cloudflare Pages Function, so `npm run dev` will not answer `/api/shares`. To run the tally locally:

```bash
cp .dev.vars.example .dev.vars
# Put a real salt in IP_HASH_SALT. The example Turnstile secret is Cloudflare's test secret.
npm run build
npx wrangler d1 migrations apply everysharevotes-sentiment --local
npx wrangler pages dev dist --port 8788 --ip 127.0.0.1
```

Open `http://127.0.0.1:8788/`. The home counter reads `GET /api/shares`. Submitting the same broker and the same signed share change twice returns a duplicate error. A different broker, or a different number, is stored. A change that would take that broker and stance below zero is rejected. Above 100,000 shares, the row is held out of the totals.

On localhost the page uses Cloudflare’s always-pass Turnstile test site key. The API refuses that test secret on any other hostname.

Refresh 13F holdings:

```bash
export SEC_CONTACT_EMAIL="you@example.com"
python3 scripts/test_thirteen_f.py
python3 scripts/fetch_13f.py
```

The script requests the SEC data-sets page, downloads the newest quarterly ZIP, and writes `public/data/holders.json`. It waits between requests and sends a User-Agent that includes the contact email. See the SEC’s fair-access notice: <https://www.sec.gov/os/accessing-edgar-data>.

## Deploy on Cloudflare Pages

The domain everysharevotes.com is already on Cloudflare. In the Pages project:

1. Connect this GitHub repository.
2. Build command: `npm run build`
3. Build output directory: `dist`
4. Root directory: the repository root (where `package.json` and `functions/` live). Pages picks up `functions/` next to the project and serves `/api/shares` from `functions/api/shares.ts`.
5. Production branch: `main`, or whichever branch you intend to publish.

### D1 binding

The ledger reads and writes a D1 database. The binding name has to be `DB`.

```bash
npx wrangler d1 create everysharevotes-sentiment
```

Copy the database id into `wrangler.toml`, replacing the all-zero placeholder:

```toml
[[d1_databases]]
binding = "DB"
database_name = "everysharevotes-sentiment"
database_id = "<id from wrangler d1 create>"
```

Apply both migrations to the remote database:

```bash
npx wrangler d1 migrations apply everysharevotes-sentiment --remote
```

`migrations/0001_sentiment.sql` is the retired one-browser poll. `migrations/0002_share_ledger.sql` is the share ledger. Apply both. The old `/api/sentiment` route is still in the repo and is not linked from the pages.

In the Pages project settings, bind the same D1 database to production and preview as the variable name `DB`. A dashboard binding is what the deployed function sees. The placeholder id in `wrangler.toml` is for local `wrangler pages dev` only and must be replaced before you rely on Wrangler to attach production.

Set these Pages secrets (production and preview):

- `IP_HASH_SALT` — a long random string. Rotating it splits returning browsers into a new identity. Never commit it.
- `TURNSTILE_SECRET_KEY` — the secret from the Cloudflare Turnstile widget you create for everysharevotes.com. Do not deploy the test secret. The function rejects the published test secret on any host other than localhost.
- `PUBLIC_TURNSTILE_SITE_KEY` — the matching site key, available at build time. The Add shares page uses Cloudflare’s test site key only when the hostname is localhost or 127.0.0.1.
- `ADMIN_REVIEW_TOKEN` — optional. `POST /api/review` with header `x-review-token` can mark a held row `counted` or `rejected`.

If `DB`, the salt, or the Turnstile secret is missing, `POST /api/shares` returns HTTP 503. The home page then shows an em dash, not a fake zero. An empty database that is configured shows 0 / 0.

### Custom domain

In the Pages project: Custom domains → set up a domain → `everysharevotes.com`. Add `www` only if you want it. Cloudflare will offer the DNS records because the zone is already on the account. Wait until the certificate shows active, then load `/`, `/the-vote`, `/holders`, and `/sentiment` over HTTPS.

Static pages do not need those secrets. The ledger does.

## Weekly 13F refresh

`.github/workflows/refresh-13f.yml` runs every Monday at 13:30 UTC and can be run by hand with `workflow_dispatch`.

1. Repository → Settings → Secrets and variables → Actions → New secret `SEC_CONTACT_EMAIL` with a monitored address.
2. The workflow needs the default `GITHUB_TOKEN` permissions this file requests: `contents: write` and `pull-requests: write`.
3. When `public/data/holders.json` changes, the workflow pushes branch `data/13f-YYYYMMDD` and opens a pull request. Review it before merging. Do not add the share column across managers. A parent and a sub-adviser can both report the same shares.

## Daily sentiment refresh

`.github/workflows/refresh-sentiment.yml` runs every day at 14:10 UTC. It runs `scripts/fetch_sentiment.py` and opens a pull request when `public/data/sentiment.json` changes. The script reads public Polymarket, Manifold, Kalshi, and GDELT endpoints. It does not need an API key. GDELT rate-limits aggressive clients; an empty media series is a real result.

Refresh institutional votes by hand:

```bash
export SEC_CONTACT_EMAIL="you@example.com"
python3 scripts/test_npx.py
python3 scripts/fetch_npx.py
```

The script pages the EDGAR full-text index, downloads the latest N-PX vote table per matching filer for the periods ended June 30, 2024 and June 30, 2026, and writes `public/data/institutional-votes.json`. Cached downloads live in `tmp/npx/`, which is gitignored.

## Data rules

Do not type a share count, a vote total, or a ledger tally into a page by hand. 13F numbers come from the generator. Vote totals come from the linked 8-K. Recommendations come from the linked article. Ledger numbers come from D1. Market and media points come from `scripts/fetch_sentiment.py`. Family votes come from `scripts/fetch_npx.py`. If a source is missing, the cell says “Not found” or the chart leaves a gap.
