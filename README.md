# Every Share Votes

An independent, neutral site for retail holders of TSLA. It explains what is on the public record about a possible combination with SpaceX, how a vote is likely to be counted, and how to cast a ballot when a proxy exists.

Jason Crawford, an independent retail shareholder, maintains the project. It is not affiliated with Tesla, Inc. or SpaceX. It is not investment advice and not a solicitation.

The brand is “Every Share Votes.” The ticker TSLA is used for the stock. The company name appears when a filing or a statute uses it.

## What is real, and what is not

Real in this repository:

- Page copy is tied to SEC filings, the Texas statute, the company’s vote guide and retail-voting page, or a named news report. Counts are the figures in those sources.
- `public/data/holders.json` is generated by `scripts/fetch_13f.py` from the SEC Form 13F data set. Every row has the filing’s EDGAR index URL, filing date, and report period.
- The poll function stores responses in D1 and returns counts from that table only.

Not filled in, on purpose:

- No proxy for a combination exists, so no record date, price, or voting standard is stated as final. The charter reading is marked unconfirmed.
- Institutional votes on past meetings are “Not found” until an N-PX filing or a press report is linked. ISS and Glass Lewis cells are filled only where a report states the recommendation. Glass Lewis on the 2016 SolarCity vote is “Not found.”
- Webull is not in Tesla’s broker list. That card points at the guide’s “all other brokers” steps.
- The poll does nothing useful until a D1 database is created and bound as `DB`. A static preview explains that. Counts are not seeded.
- The weekly Action opens a pull request only when the holdings JSON changes. Set the `SEC_CONTACT_EMAIL` secret to a mailbox a person reads. Until then the script falls back to `contact@everysharevotes.com` and prints a warning.

## Local development

Requires Node 20 or newer and Python 3.12.

```bash
npm install
npm run dev
```

The dev server is Astro. The sentiment poll is a Cloudflare Pages Function, so `npm run dev` will not answer `/api/sentiment`. To run the poll locally:

```bash
npm run build
npx wrangler d1 migrations apply everysharevotes-sentiment --local
npx wrangler pages dev dist --port 8788
```

Open `http://127.0.0.1:8788/sentiment`. The first response creates the local cookie. A second POST from the same browser does not change the tally.

Refresh 13F holdings:

```bash
export SEC_CONTACT_EMAIL="you@example.com"
python3 scripts/test_thirteen_f.py
python3 scripts/fetch_13f.py
```

The script requests the SEC data-sets page, downloads the newest quarterly ZIP, and writes `public/data/holders.json`. It waits between requests and sends a User-Agent that includes the contact email. See the SEC’s fair-access notice: <https://www.sec.gov/os/accessing-edgar-data>.

## Deploy on Cloudflare Pages

The domain everysharevotes.com is already on Cloudflare. In the Pages project:

1. Connect this GitHub repository.
2. Build command: `npm run build`
3. Build output directory: `dist`
4. Root directory: the repository root (where `package.json` and `functions/` live). Pages picks up `functions/` next to the project and serves `/api/sentiment` from `functions/api/sentiment.ts`.
5. Production branch: `main`, or whichever branch you intend to publish.

### D1 binding

The poll reads and writes a D1 database. The binding name has to be `DB`.

```bash
npx wrangler d1 create everysharevotes-sentiment
```

Copy the database id into `wrangler.toml`, replacing the all-zero placeholder:

```toml
[[d1_databases]]
binding = "DB"
database_name = "everysharevotes-sentiment"
database_id = "<id from wrangler d1 create>"
```

Apply the schema to the remote database:

```bash
npx wrangler d1 migrations apply everysharevotes-sentiment --remote
```

In the Pages project settings, bind the same D1 database to production and preview as the variable name `DB`. A dashboard binding is what the deployed function sees. The placeholder id in `wrangler.toml` is for local `wrangler pages dev` only and must be replaced before you rely on Wrangler to attach production.

If `DB` is missing, `GET /api/sentiment` returns HTTP 503 and the page says the poll is not configured. It does not show a zero tally in that case.

### Custom domain

In the Pages project: Custom domains → set up a domain → `everysharevotes.com`. Add `www` only if you want it. Cloudflare will offer the DNS records because the zone is already on the account. Wait until the certificate shows active, then load `/`, `/the-vote`, `/holders`, and `/sentiment` over HTTPS.

No environment variables are required for the static pages. The poll uses the D1 binding, not a secret.

## Weekly 13F refresh

`.github/workflows/refresh-13f.yml` runs every Monday at 13:30 UTC and can be run by hand with `workflow_dispatch`.

1. Repository → Settings → Secrets and variables → Actions → New secret `SEC_CONTACT_EMAIL` with a monitored address.
2. The workflow needs the default `GITHUB_TOKEN` permissions this file requests: `contents: write` and `pull-requests: write`.
3. When `public/data/holders.json` changes, the workflow pushes branch `data/13f-YYYYMMDD` and opens a pull request. Review it before merging. Do not add the share column across managers. A parent and a sub-adviser can both report the same shares.

## Data rules

Do not type a share count, a vote total, or a poll tally into a page by hand. 13F numbers come from the generator. Vote totals come from the linked 8-K. Recommendations come from the linked article. Poll numbers come from D1. If a source is missing, the cell says “Not found.”
